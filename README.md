# Сегодня

Мобильный план дня с двумя разделами: «Сегодня» (временная шкала, свободные окна, локальные отметки и тренировка) и «Расписание» (постоянные школьные уроки). Обычные HTML, CSS и JavaScript, без сервера и устанавливаемых зависимостей.

**Текущий комплект содержит пример на 6 октября 2026 года, а не подтверждённое личное расписание.** Программа тоже демонстрационная. История тренировок пустая. Перед реальным использованием ежедневный агент заменяет пример на согласованный план.

## Ежедневное обновление

Читай [AGENT_INSTRUCTIONS.md](AGENT_INSTRUCTIONS.md). Разрешены только:

- `data/today.json` — день и события;
- `data/workout.json` — программа или `null`;
- `data/workout-history.json` — подтверждённые результаты.

`data/school-schedule.json` — постоянное расписание: ежедневный агент читает его, но изменяет только по отдельному прямому запросу пользователя.

`data/config.json`, интерфейс и инфраструктура остаются постоянными. Машинные схемы находятся в `schemas/`. Валидатор проверяет JSON, неизвестные поля, диапазоны, существование даты и связи между файлами.

```sh
node scripts/validate.mjs
```

Нужен Node.js 22+. Установка npm-пакетов не требуется. Связанные файлы обновляй одним атомарным коммитом.

## Проверка локально

Открой сайт через HTTP, не двойным щелчком по HTML: браузер не обязан разрешать `fetch` из `file://`.

```sh
python3 -m http.server 8080
```

Открой `http://localhost:8080/`. Проверь ширину около 390 px, галочки, перезагрузку, экран тренировки и возврат к дню. Проверка в реальном Safari на iPhone остаётся отдельным этапом; изменение viewport не равно проверке на физическом устройстве.

## GitHub Pages — настройка один раз

Репозиторий создаётся отдельно; существующие проекты не изменяются. Публичность сначала согласуется с владельцем. Возможности приватного репозитория зависят от тарифа: [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages). Публичный сайт на личном аккаунте доступен посетителям без входа, включая опубликованные JSON.

1. Создать согласованный репозиторий `daily-planner`, основная ветка `main`.
2. Добавить весь этот проект, включая `.github/workflows/pages.yml`.
3. В Settings → Pages → Build and deployment выбрать **GitHub Actions**.
4. Запустить `Validate and publish Today` или отправить следующий коммит в main.
5. Дождаться успешного deployment и открыть URL, показанный в Settings → Pages. Проверить именно работающий сайт, а не только workflow.

Workflow сначала валидирует данные и синтаксис JavaScript. Если они неверны, deployment не запускается. В артефакт входят только HTML, CSS, JS, иконки, manifest и `today/workout/config/school-schedule`. История и документация не публикуются в Pages-артефакте; в публичном исходном репозитории они всё равно видимы. Источники: [настройка публикации](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site), [пользовательский workflow](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## iPhone

В Safari открыть опубликованную ссылку → «Поделиться» → «На экран Домой». Есть mobile viewport, safe-area отступы, Apple touch icon и standalone manifest. Service worker и офлайн-кэш не используются, чтобы не показывать вчерашний план из кэша. Отметки локальны и не синхронизируются с другим устройством, другой браузерной сессией или историей GitHub.

## Устойчивость

- Данные запрашиваются без браузерного кэша, с уникальным параметром URL и таймаутом.
- При открытии и возврате на вкладку данные перечитываются; есть ручное обновление.
- Если дата плана отличается от даты в Москве, показывается предупреждение.
- Ошибка загрузки не оставляет пустой экран. При неудачном обновлении уже открытый план остаётся с предупреждением.
- Отсутствие программы не ломает основной день. Несовпадающая дата/id не показывают старую тренировку.
- Текст данных вставляется через `textContent`, без выполнения HTML.
- Пересечения учитываются в занятости, свободные окна не перекрывают события.
- Нет регистрации, календарной интеграции, AI внутри сайта или автоматического обновления GitHub из браузера.

Приватность: хранить только итоговый план и программу. Никаких персональных сведений о здоровье, ответов пользователя, секретов и причин выбора программы. Схема ограничивает поля, но смысл свободного текста проверяет агент перед коммитом.
