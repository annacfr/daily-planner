# DAILY AGENT — READ THIS FIRST

YOU MAY EDIT:
- `data/today.json`
- `data/workout.json`
- `data/workout-history.json`

YOU MAY READ BUT MUST NOT EDIT DURING DAILY PLANNING:
- `data/school-schedule.json`

DO NOT EDIT:
- `index.html`, `css/*`, `js/*`, `assets/*`
- `data/config.json`
- `data/school-schedule.json` — кроме отдельного прямого запроса пользователя изменить постоянное расписание
- `schemas/*`, `scripts/*`, `package.json`
- `.github/*`, настройки GitHub Pages
- `manifest.webmanifest`, `.nojekyll`, `.gitignore`
- `README.md`, `AGENT_INSTRUCTIONS.md` и любые другие файлы

Эта инструкция разрешает обычное ежедневное обновление только трёх файлов данных. Изменение кода, схемы, настроек, доступа или постоянного школьного расписания требует отдельного прямого запроса пользователя. Не нужно читать весь код: прочитай эту инструкцию и пять файлов в `data/`.

## 1. Приватность — обязательное правило

Не записывай в проект, Git, сообщения коммитов, описания PR, комментарии, логи или браузерное хранилище никаких сведений о менструации, фазе цикла, симптомах, боли, диагнозах, здоровье, энергии или ежедневных ответов о самочувствии. Не сохраняй ни значения, ни даты этих сведений, ни объяснение причины выбора нагрузки. Не добавляй скрытых полей и файлы для таких данных. Сайт получает только итоговую программу упражнений.

Это правило относится также к свободному тексту `summary`, `title`, `description`, `name`, `reps`, `note`. `note` — только краткая техническая подсказка к движению. Перед коммитом прочитай весь diff и проверь содержание. Проверка схемы отвергает лишние поля, но не распознаёт чувствительные сведения в произвольном тексте; она не заменяет проверку приватности.

Сайт GitHub Pages на личном аккаунте обычно публичен, даже когда репозиторий приватный. Не добавляй адреса, контакты, учебное заведение, место нахождения, секреты, ключи и токены. Используй общие названия событий.

## 2. Формат и общие правила

- Кодировка UTF-8. Только стандартный JSON: без комментариев, завершающих запятых, `undefined`, `NaN`.
- `schema_version` всегда число `1`. Не меняй версию.
- Дата — строка `YYYY-MM-DD`, реальная календарная дата.
- Время — строка `HH:MM`, 24-часовой формат, `00:00`–`23:59`.
- Все даты и времена плана — гражданское время `Europe/Moscow`. Не используй часовой пояс устройства или среды выполнения.
- `id`, `workout_id` — 1–64 символа, строчные латинские буквы, цифры, `_`, `-`; первый символ буква или цифра: `^[a-z0-9][a-z0-9_-]*$`.
- Неизвестные поля запрещены во всех объектах. Машинные схемы: `schemas/*.schema.json`, JSON Schema 2020-12.
- Текстовые поля должны содержать непробельный текст. Необязательное поле без значения удаляй, не записывай `null` или пустую строку.
- Сохраняй id существующего события, если это та же задача: локальные галочки связаны с датой и id. Для другой задачи используй новый id.
- Не выдумывай личное расписание, выполненные упражнения, подходы, повторы или результаты. Не переносись автоматически со вчерашнего плана: сначала получи актуальные источники и необходимые ответы.

## 3. `data/today.json`

| Поле | Обязательно | Формат |
|---|---|---|
| `schema_version` | Да | `1` |
| `date` | Да | `YYYY-MM-DD` |
| `schedule` | Да | Массив 0–60 событий |
| `summary` | Нет | Строка 1–120 символов, короткая сводка |
| `is_example` | Нет | Boolean, `true` только для демонстрации |
| `school_mode` | Нет | `auto` (по умолчанию) или `none`, если школы сегодня совсем нет |

Поля каждого события:

| Поле | Обязательно | Формат |
|---|---|---|
| `id` | Да | Уникальный в этом дне id |
| `start`, `end` | Да | `HH:MM`, start строго раньше end |
| `title` | Да | Строка 1–120 символов |
| `type` | Да | `school`, `study`, `work`, `home`, `personal`, `workout` |
| `description` | Нет | Строка 1–240 символов |
| `workout_id` | Только у тренировки | Ссылка на `workout.json.id` |

`type: "workout"` — единственный признак тренировки; отдельное логическое поле не нужно. В первой версии поддерживается максимум одна тренировка в день. Приоритеты не используются.

Отсортируй `schedule` по `start` от ранних к поздним. Избегай пересечений: проверь исходный календарь, добавь нужные перерывы и дорогу как отдельные события, если они запланированы. Валидатор предупреждает о пересечениях; сайт показывает предупреждение и не называет занятые интервалы свободными. События через полночь не поддерживаются: раздели их на два дня, указывая в сегодняшнем файле только сегодняшнюю часть.

Добавить событие: вставь объект в `schedule` в порядке времени. Удалить событие: удали весь объект. Свободные окна не записывай событиями; сайт вычисляет их по `start/end` и `config.json`. Не добавляй другие типы, например `free` или `travel`; для дороги подходит `personal` с названием «Дорога».

Реальный план: удали `is_example` или поставь `false`. При отсутствии `summary` сайт покажет «План дня». Текст сводки должен соответствовать плану. Начальная версия содержит явно помеченный пример, взятый из задания; это не подтверждённое расписание пользователя.

Пример дня без тренировки (иллюстрация схемы):

```json
{
  "schema_version": 1,
  "date": "2026-10-06",
  "summary": "1 дело · вечер свободен",
  "schedule": [
    {"id":"study","start":"15:30","end":"17:30","title":"Учёба","type":"study"}
  ]
}
```

## 4. `data/workout.json`

Если тренировки нет: весь файл должен содержать JSON-значение `null` и завершающий перевод строки. Не удаляй файл, не оставляй пустые байты и не записывай `{}`. Пустой или недоступный файл не ломает интерфейс, но не проходит проверку публикации.

Если тренировка есть: файл содержит один объект:

| Поле | Обязательно | Формат |
|---|---|---|
| `schema_version` | Да | `1` |
| `id` | Да | Совпадает с `workout_id` события |
| `date` | Да | Равна `today.json.date` |
| `title` | Да | Строка 1–120 символов |
| `duration_minutes` | Да | Целое число 1–180, не длиннее окна события |
| `warmup` | Да | Массив 0–20 упражнений |
| `main` | Да | Массив 1–30 упражнений |
| `cooldown` | Да | Массив 0–20 упражнений |
| `is_example` | Нет | Boolean; должен совпадать по смыслу с today |

Схема упражнения общая для всех трёх частей и истории:

| Поле | Обязательно | Формат |
|---|---|---|
| `name` | Да | Строка 1–100 символов |
| `muscle_groups` | Да | 1–10 уникальных значений из таблицы ниже |
| `sets` | Для упражнения по повторам | Целое число 1–20, всегда вместе с `reps` |
| `reps` | Для упражнения по повторам | Строка 1–40 символов: `10–12` или `10, затем 15` |
| `duration_minutes` | Для упражнения по времени | Целое число 1–180 |
| `rest_sec` | Нет | Целое число 0–600 |
| `note` | Нет | Только техника движения, строка 1–240 символов |

Каждое упражнение должно иметь либо пару `sets` + `reps`, либо `duration_minutes`; можно оба варианта одновременно, если это действительно необходимо. Не добавляй вес, самочувствие или причину выбора программы.

| Значение `muscle_groups` | Смысл |
|---|---|
| `quadriceps` | Передняя поверхность бедра |
| `hamstrings` | Задняя поверхность бедра |
| `glutes` | Ягодицы |
| `back` | Спина |
| `chest` | Грудь |
| `arms` | Руки |
| `core` | Корпус |
| `cardio` | Кардио |
| `mobility` | Подвижность |
| `full_body` | Всё тело |

База уже используемых упражнений: эллиптический тренажёр, гиперэкстензия, жим ногами, румынская тяга, разгибание ног, сгибание ног, тяга верхнего блока, горизонтальная тяга, подтягивания в гравитроне, отжимания в гравитроне, сведение рук / pec deck. Это перечень для составителя, а не автоматически назначенная программа. Не назначай высокую нагрузку в горизонтальной тяге без подтверждённой уверенной техники. Сам сайт упражнения не выбирает.

Обновляй `today` и `workout` вместе, одним атомарным коммитом. Если дата или id программы не совпадают, сайт покажет «Программа пока недоступна», не вчерашнюю тренировку.

## 5. `data/workout-history.json`

Корень: `{"schema_version":1,"sessions":[]}`. Начальная история пустая: подтверждённых тренировок для неё нет. `sessions` — массив 0–10000 записей от старых к новым.

| Поле записи | Обязательно | Формат |
|---|---|---|
| `id` | Да | Уникальный id записи, например `2026-10-06-gym` |
| `workout_id` | Да | Id выполненной программы; старый id не обязан совпадать с сегодняшним |
| `date` | Да | Реальная дата, не позже даты today |
| `duration_minutes` | Да | Подтверждённая длительность, целое 1–180 |
| `status` | Да | `completed` или `partial` |
| `exercises` | Да | 1–70 фактически выполненных упражнений по общей схеме |

Проверка недавней нагрузки: прочитай последние 3–5 записей массива, даты и `exercises[].muscle_groups`. Сравни упражнения и фактические подходы/повторы. Эти метки описывают категории упражнений; сами по себе они не дают основания утверждать восстановление или назначать нагрузку.

Добавление: получи подтверждение выполнения, даты, длительности и состава; добавь запись с уникальным id. Записывай фактические подходы и повторы. Если все данные ещё не подтверждены, не создавай запись; уточни недостающее, не копируй план как результат. Не включай пример программы в историю. `partial` — только подтверждённая частично выполненная тренировка. Исправление записи по уточнённым данным сохраняет её id. Не дублируй уже зарегистрированную тренировку.

Галочки сайта локальны и не синхронизируются с GitHub. Агент не может узнать их состояние из JSON. Снятие/установка галочки не создаёт запись истории. В историю попадёт только результат, отдельно подтверждённый пользователем.

## 6. `data/config.json` — только чтение

Обязательные поля: `schema_version: 1`, `timezone: "Europe/Moscow"`, `day_start`, `day_end`, `morning_end`, `evening_start` (строки времени), `min_free_minutes` (целое 1–120).

Порядок: `day_start < morning_end < evening_start < day_end`. Начальные границы: 07:00, 12:00, 18:00, 23:00; минимальное показываемое окно 20 минут. Это параметры отображения, не обещание времени бодрствования. События за пределами границ расширяют отображаемый день. Пересекающее границу событие показывается один раз в части дня по времени начала. Свободные окна считаются по объединению всех занятых интервалов.

## 7. `data/school-schedule.json` — постоянные данные, только чтение

Этот файл содержит базовое школьное расписание с понедельника по пятницу в часовом поясе `Europe/Moscow`. Ежедневный агент обязан читать его при составлении дня, но не имеет права изменять его в ходе обычного ежедневного планирования. Изменение разрешено только по отдельному прямому запросу пользователя, например: «Измени школьное расписание: по средам теперь…».

Корневые поля:

| Поле | Формат |
|---|---|
| `schema_version` | Всегда `1` |
| `timezone` | Всегда `Europe/Moscow` |
| `lesson_times` | Восемь непересекающихся интервалов с `number`, `start`, `end` |
| `weekdays` | Объект с ключами `monday`, `tuesday`, `wednesday`, `thursday`, `friday` |

Каждый элемент дня содержит только `number` (номер урока) и `subject` (название предмета). Номера идут с 1 подряд, уникальны и ссылаются на `lesson_times`. Учителей, кабинеты и временные исключения в этот файл не добавляй.

При утреннем планировании сопоставь текущую дату в Москве с нужным днём `weekdays`, учти уроки вместе с Google Calendar и дополнительными делами. Сайт автоматически добавляет на экран «Сегодня» единый блок «Школа» от начала первого до конца последнего урока, если в `today.json` нет события с `type: "school"`. Поэтому в обычный учебный день школьный блок вручную не добавляй.

Опоздание, ранний уход, пропуск, отменённый урок или разовая перестановка относятся только к конкретной дате. В таком случае добавь в `today.json` один фактический блок с `type: "school"`; он заменит автоматический интервал. Если школы в этот учебный день совсем нет, установи корневое поле `"school_mode": "none"`. Не меняй `school-schedule.json`. Постоянный файл — базовая версия; `today.json` — фактический сегодняшний план.

## 8. Порядок ежедневного обновления

1. Установи актуальную дату в Москве. Прочитай текущие пять файлов данных, включая постоянное школьное расписание, и последние записи истории.
2. Учти уроки текущего дня из `school-schedule.json`, Google Calendar, другие авторизованные источники и необходимые короткие ответы пользователя. Не публикуй ответы пользователя в репозитории. Разовые изменения школы применяй только к `today.json`.
3. Составь выполнимый план с перерывами. При наличии тренировки сформируй итоговую программу отдельно. Проверяй длительность и соответствие id.
4. Запиши только три разрешённых файла по необходимости. Без тренировки запиши `null` в workout. Не меняй историю без подтверждённого результата.
5. Проверь JSON и связи данных командой из корня репозитория:

   ```sh
   node scripts/validate.mjs
   ```

   Нужен Node.js 22 или новее; `npm install` не требуется. Ожидается код выхода 0 и `OK`. Ошибки исправляй только в разрешённых файлах. Не отключай проверку и не меняй схемы ради прохождения.
6. Просмотри diff: при обычном ежедневном обновлении в нём только три разрешённых пути; `school-schedule.json` не изменён; нет чувствительных сведений, лишних данных и изменений инфраструктуры. Проверь свободный текст вручную. Пересечения должны быть объяснены исходным расписанием или исправлены, а не игнорироваться.
7. Опубликуй все связанные изменения одним коммитом. При работе через GitHub connector можно создать tree на основе текущего tree, затем commit с текущим parent и обновить main с `expected_sha` текущего head и `force: false`. Это предотвращает частичную публикацию и потерю чужих изменений. Если доступны только пофайловые изменения — делай их в отдельной ветке и затем объединяй полную проверенную ветку; не меняй main последовательно отдельными коммитами today/workout.
8. При конфликте head получи новый актуальный head, перечитай данные, сохрани новые результаты пользователя и повтори проверку. Не используй force push.
9. Дождись успешного `Validate and publish Today`. Если проверка не прошла, исправь данные. Не объявляй публикацию успешной по факту коммита.
10. Открой действительный URL Pages, полученный из GitHub Settings → Pages или результата deployment. Нажми «Обновить». Проверь видимую дату, сводку, все события и программу. Сверь `data/today.json?v=<уникальное-значение>` и `data/workout.json?v=<уникальное-значение>` на опубликованном адресе с ожидаемыми файлами. Если они устарели, дождись завершения публикации и повтори проверку. При ширине около 390 px проверь отсутствие горизонтального скролла и доступность кнопок.
11. Только после реальной проверки сообщи кратко об обновлении. Если инструменты не дают открыть сайт или доступ потерян, прямо укажи непроверенный этап, не заявляй успех.

## 9. Поведение при ошибках и границы системы

- Необязательные описания и summary могут отсутствовать.
- Повреждённые обязательные данные дня дают спокойное сообщение. Некорректные отдельные события пропускаются с предупреждением.
- Пустой/недоступный workout даёт сообщение в программе и не скрывает день. При отсутствии тренировок ссылка не показывается в плане.
- Повреждённый config заменяется обычными границами дня; агент всё равно не должен менять config.
- Повреждённое или недоступное школьное расписание даёт спокойное сообщение только во вкладке «Расписание» и не ломает раздел «Сегодня».
- Галочки сохраняются по ключу с путём сайта, датой и id событий. Они доступны только в этом браузере/устройстве. В приватном режиме или при запрете storage сайт работает, но может не сохранить отметки. Для возврата в невыполненные нажми тот же переключатель.
- Сайт не подключается к календарю, не хранит ответы и не формирует программы. Автоматизация настраивается отдельно; нельзя обещать её работу до проверки доступа будущей задачи к источникам и записи в GitHub.
- Нет service worker: данные обновляются при открытии, возврате на страницу и кнопкой «Обновить». Для загрузки нужен интернет.
- История и инструкции не включаются в Pages-артефакт. Однако в публичном репозитории они доступны через GitHub; не считай их приватными.
